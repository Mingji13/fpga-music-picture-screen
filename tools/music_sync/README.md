# 音乐画屏：PC 卡点分析与试听工具

本工具在电脑上处理音乐，输出候选拍点、试听文件及切图时间表。FPGA 不做实时节拍识别。
CUE 读取已接入本提交工程 RTL。FPGA 工程构建方法见根目录 README.md。

## 最容易的用法

1. 双击本目录的 `run.cmd`，选择 WAV 或 PCM；也可以将文件拖到 `run.cmd` 上。
2. 等待分析完成，浏览器会打开这一首歌的 `review.html`。
3. 点“播放”，先听“音乐＋每拍提示”：普通拍轻响，小节第一拍高响。
4. 如果拍子跟得对，但小节起点错了一拍，用“前移一拍／后移一拍”。
   也可以暂停在一个确定的小节第一拍附近，点“以当前位置设第一拍”。自动模式会吸附到最近候选拍。
5. 默认每两小节切换一次。切换到“音乐＋切图点”，听预定切图位置，页面会同时显示模拟画面编号。
6. 在歌曲开头、中段、结尾及节奏变化处试听。确认后勾选“我已试听并确认”，下载 JSON。
   也可以下载当前切图试听 WAV，发给别人或用普通播放器试听。

第一次建立环境需要网络。使用本目录独立的 Python 3.12 环境，依赖不会安装到全局环境。
安装依赖后，再次分析不需要联网。全部音频分析在本机完成，不上传音乐。
浏览器页面自带音乐数据，可直接双击打开，无需服务器或网络。

## 分析结果意味着什么

- 输入 WAV：调用现有 `tools/make_audio_corpus.py`，先转换成板上真正使用的格式。
- 输入 PCM：必须已是 **48000 Hz、单声道、16 位有符号小端、无文件头**；工具无法从无头数据自动辨认格式。
- 不裁剪静音、不改变播放速度；正式 PCM 不加入提示音。
- librosa 在 PC 上使用频谱起音和动态规划寻找节拍。默认使用全曲节奏先验，复杂变速/弱起/自由前奏可能失准。
- **每小节拍数默认假定为 4，不会自动识别拍号。** 3 拍音乐要手动改为 3；6/8 的分组需按试听选择合适的拍层级。
- 第一拍建议使用低频/全频起音的重复重音评分，属于启发式候选，**不是可靠的语义小节识别模型**。
  特别是钢琴曲，最强的起音不一定是小节第一拍。时间表默认 `reviewed=false`，不能当成已校准结果。
- BPM 可能被识别成一半或两倍。固定 BPM 模式可用于速度稳定、速度和第一拍已确认的曲子；
  歌曲变速时不要强行使用固定网格。本版尚无分段编辑器，复杂曲目需要后续增加分段校准。
- 自动分析时间分辨率约 5.33 ms。保存为样本序号只是确保执行位置明确，不代表自动识别精确到一个样本。

## 输出内容

每次创建新目录 `runs/日期时间_歌名/`，绝不覆盖原歌曲或已有运行目录。

| 文件 | 用途 |
| --- | --- |
| `audio.pcm` | 正式音频，与现有板上格式一致 |
| `music.wav` | 同一份 PCM 加 WAV 头，方便试听 |
| `beats_preview.wav` | 音乐＋普通拍/候选小节第一拍提示音 |
| `cuts_preview.wav` | 音乐＋候选切图提示音 |
| `review.html` | 可播放、调整和导出的独立校准页面 |
| `schedule.json` | 拍点、参数、切图样本位置及 PCM 的 SHA256 |
| `cues.csv` | 便于查看的切图位置表 |

目录内 WAV/JSON 是本次生成时的结果。在网页内调整不会自动改写这些文件，需要点下载保存新结果。
下载的 JSON 可再次交给 `render`，校验音频后生成新的整套结果。浏览器下载的 CSV 仅用于查看；
JSON 保留绑定音频的 SHA256、是否确认等信息，CUE 导出器以它为准。

试听混音会统一降低音乐音量以容纳提示音；正式 `audio.pcm` 不受影响。
页面的模拟画面编号用于观察切图时刻，不代表实际 SD 卡图片编号或正式转场特效。

## 将确认的时间表导出为 CUE

1. 双击 `export_cue.cmd`，先选择已试听确认并下载的 JSON。
2. 再选择实际要放到 SD 卡的 `SONG1.PCM`～`SONG16.PCM`，不能选试听提示音 WAV。
3. 工具核对音频内容和时间表后，在 PCM 旁生成同编号文件，例如 `SONG2.CUE`。

也可把 JSON 拖到 `export_cue.cmd` 上，再选择配套 PCM。不需要重新分析歌曲。
JSON 必须标记为已确认，所选 PCM 必须与试听时使用的正式 PCM 完全一致。
改过音频内容后，需要重新分析和确认；只改成 `SONG编号.PCM` 的文件名不影响校验。
导出不会覆盖已有 CUE；要重新导出时，先自行保留旧文件，再用 `--output` 指定另一目录中的同编号 CUE。

使用支持 CUE 的新位流，将配套的 `SONG2.PCM` 和 `SONG2.CUE` 一起复制到 SD 卡根目录；JSON 不必放到卡上。
只有 WAV 模式且自动轮播开启时使用卡点。无同编号 CUE 或点表校验失败时，仍按原来的定时间隔轮播。
CUE 是本工程自定义的二进制切图点表，详见 [CUE_FORMAT.md](CUE_FORMAT.md)。

## 命令行

在本工具目录的 PowerShell 中：

```powershell
# 自动分析：省略文件名也会弹出选择窗口。
& .\.venv\Scripts\python.exe .\music_sync.py analyze 'D:\music\SONG1.PCM' --open

# 确定是 120 BPM、4 拍，小节参考第一拍在 1.3 秒：
& .\.venv\Scripts\python.exe .\music_sync.py analyze 'D:\music\SONG1.PCM' --grid --bpm 120 --first-downbeat 1.3 --bars 2

# 只从 10 秒后的合格小节开始切图，不重新改变小节相位：
& .\.venv\Scripts\python.exe .\music_sync.py analyze 'D:\music\SONG1.PCM' --start-after 10

# 将网页下载的 JSON 渲染成新试听文件。PCM 必须与该表的 SHA256 完全匹配。
& .\.venv\Scripts\python.exe .\music_sync.py render 'D:\music\reviewed_schedule.json' --pcm '.\runs\某次结果\audio.pcm'

# 已确认的 JSON → 同编号 CUE，默认输出在 PCM 旁边，不覆盖已有文件：
& .\.venv\Scripts\python.exe .\music_sync.py export-cue 'D:\music\reviewed_schedule.json' --pcm 'D:\music\SONG2.PCM'

# 检查已有 CUE 的格式、校验和及其是否匹配 PCM：
& .\.venv\Scripts\python.exe .\music_sync.py inspect-cue 'D:\music\SONG2.CUE' --pcm 'D:\music\SONG2.PCM'

# 必要的自动检查：
& .\.venv\Scripts\python.exe .\test_music_sync.py
& .\.venv\Scripts\python.exe .\test_cue_export.py
```

`--bpm` 单独使用是自动跟拍的速度约束；搭配 `--grid` 才生成严格等间隔网格。
`--first-downbeat` 在跟拍模式下选择最近的候选拍；固定网格模式下直接使用指定位置。
计时从正式 PCM 的第 0 个样本开始；固定网格每个位置独立计算取整，不累加整数拍长造成漂移。
第一条切图命令可以发生在参考第一拍；此前保持首图。若希望首图多停留一些时间，可设置跳过开头秒数。

## FPGA 播放行为

只在 WAV 模式且自动轮播开启时使用卡点。时间表表示“在此样本开始转场”。
FPGA 以实际取出的文件样本计数；启动等待、暂停和 FIFO 缺数据时补的零不计数，文件本身的静音照常计数。
切歌、单曲循环时从样本 0 和首个点重新开始；曲中开启自动轮播不会补切过去的点。
转场正忙或下一图未就绪时跳过当前点，不排队补切。末点之后保持当前图，直到歌曲重播或切歌。
其他音频模式保持原定时轮播，手动切图保持原逻辑。
JSON/CSV 用于电脑端校准和查看，FPGA 只读取同编号 CUE。每首最多 1024 个点，仅在播放前加载当前曲的点表。

## 本次验证

`test_music_sync.py` 检查固定网格长期计时、跳过前奏后的小节相位、提示音样本位置、
合成 120 BPM 音频的跟拍、静音输入、输入文件保护、音频哈希绑定和拒绝错误时间表。
`test_cue_export.py` 检查二进制字节布局、校验和、截断/损坏文件、位置边界、
未确认时间表拒绝导出、同长度不同音频的拒绝、同编号配对和已有文件保护。
`test_review.py` 在本机 Chrome 无界面模式检查页面播放、参数校准、导出 JSON/WAV、
渲染往返及错误输入；它额外需要 `playwright==1.58.0`，普通用户运行工具不需要该测试依赖。
自动检查只能验证实现和数据一致性，不能替代真实歌曲的小节听感确认。
